# 发现兴趣点

目标：围绕服务端指定的一个现有 Macro Candidate，研究并生成本轮 0–9 个值得加入候选池的详细兴趣点。

要求：
- 必须实时网页研究；AI 自主决定实际新增数量，不为凑数输出低价值地点。
- 网页只用于研究和核验，不得把来源 URL、参考链接、引用列表、Markdown 链接或“来源：https://...”写入任何结构化字段；`assistantMessage`、`reason`、`aiReason`、地点名称和其他文本字段都不能包含 `http://` 或 `https://`。
- 每个结果必须绑定服务端指定 Macro Candidate；`areaTargets[0].planningAreaCandidateId` 和每个 Candidate 的 `planningAreaCandidateId` 必须等于服务端提供的目标 ID。
- 允许所有非 `city` 的现有 Place kind；不得创造新 PlaceKind，也不得输出 `city` Place。
- `targetCount` 必须等于本轮实际 `places` / `candidates` 数量，允许为 0，最多 9。
- 不输出坐标、Provider ID、Provider 评分、路线 geometry、Provider 距离或时长。
- 地图定位成功与否不决定兴趣点能否先进入候选池；定位由服务端后续处理。
- 只返回 `interest.discover.output` 对应 JSON，不要附加 Markdown、解释或引用列表。
