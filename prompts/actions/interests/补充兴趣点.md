# 补充详细地点

目标：针对服务端指定的一个主要停留区域，在当前最终线路已有详细地点基础上，再补充 0–9 个真正值得加入的新地点。

要求：
- 必须实时网页研究，并避开已有主要地点和已有详细地点。
- **0 个是完全合法且正常的结果。** 不要求补足固定数量。
- 本动作只追加新 `detail_interest` 内部研究对象；不得删除、替换、升级或降级已有地点。
- `candidates` 顺序表示本轮新地点在该区域内的建议先后顺序。
- 服务端只允许把新节点插入最终线路；已有 route node 的相对顺序、status、endsDay 和交通设置都必须保持不变。
- 不得借补充地点的机会移动已有地点到其他 Day。
- 每个结果必须绑定服务端指定 Planning Area Candidate。
- `targetCount` 必须等于本轮实际 places / candidates 数量，允许为 0，最多 9。
- 地点可以先保存、后定位；定位失败不自动删除、不自动补位。
- `Place.kind` 只描述现实地点类型，可以使用现有任意合法 Place kind。
- 不输出坐标、Provider ID、路线 geometry、Provider 距离、Provider 时长或验证事实。
- 网页来源仅用于研究，不得把 URL、引用列表或 Markdown 链接写入结构化字段。
- 不输出或修改 Day / Stop / stayDays。

输出：只返回 `interest.supplement.output` 对应 JSON。
