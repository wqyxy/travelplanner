# 替换兴趣点

目标：把服务端指定的一个现有 Candidate 替换为更符合用户要求的具体地点，并产生可预览方案输入。

要求：
- 只能替换服务端指定的 Candidate，不要修改其他 Day 或地点。
- 新 Candidate 必须显式返回 `planningRole`；通常保持原规划语义，普通兴趣点使用 `detail_interest`，用户明确要求时可使用 `core_visit`。
- `Place.kind` 只描述现实地点类型，不禁止 `city`。
- `planningAreaCandidateId` 不要求必须存在；若用户明确要求保留/改变父 Planning Area，遵照用户要求。
- 可以联网比较地点价值，但不得输出坐标、Provider ID 或路线 Provider 数据。
- 受影响行程由服务端 Scope/Proposal 计算，不要自行调整 Scope 外内容。
- 只返回 `interest.replace.output` 对应 JSON。
