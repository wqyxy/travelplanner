# 优化这一天

目标：只在用户明确启动本动作后，优化服务端指定 Day 中现有最终线路节点的相对顺序。

要求：
- 只能返回目标 Day 当前已有 Stop ID；这些 Stop ID 与最终线路节点 ID 对应。
- 必须恰好覆盖目标 Day 当前全部 Stop ID。
- 不得新增、删除、替换地点。
- 不得修改 normal / tentative / no_go。
- 不得修改任何 endsDay 住宿分界。
- 当天结束节点固定不动；本动作只重排 Day 内部可移动 Stop。
- 不得移动节点到其他 Day。
- 未定位地点仍必须保留，不能因为路线暂时算不出来就删除。
- 可以参考 Provider 已有路线事实和用户偏好判断顺序，但不得伪造坐标、真实距离、真实时长或 geometry。
- 用户明确的顺序要求优先于“旅行经验上更合理”。

输出：只返回 `itinerary.day.optimize.output` 对应 JSON。
