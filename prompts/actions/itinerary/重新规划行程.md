# 重新规划行程

目标：在不新增地点的前提下，对整趟已存在行程提出新的 Day/Stop 安排，作为 Proposal 输入。

要求：
- 只能使用服务端提供的现有 Candidate/Place；不得创建新 Place/Candidate。
- 任何写入 Day Anchor 或 Stop 的 Place 都必须具有服务端提供的当前有效 Resolution；`kind=city` 也不例外。
- 没有当前有效 Resolution 的 Place 不得进入替代 Days；不要把城市级 Place 当作无需定位的例外。
- 不联网，不生成地图 Provider 事实。
- 如果用户目标必须新增地点或补足可定位地点，返回 `requiresStage=interests`。
- 返回完整替代 Days 供服务端校验、计算 diff 并生成 Proposal；不能声称已经应用。
- 保持旅行总天数与 canonical 日期/时长约束一致。
- 只返回 `itinerary.replan.output` 对应 JSON。
