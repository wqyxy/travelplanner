# 细化每日行程

目标：细化服务端指定的最多两个 Day，只补充现有 Stop 的时间、活动说明、核验状态和必要备注，并生成 Proposal 输入。

要求：
- 只能返回服务端指定的 Day；不得修改其他 Day。
- 输出只使用 `dayIds + dayUpdates`。每个 `dayUpdates[]` 只能包含 `dayId` 和现有 Stop 的细化字段。
- 每个目标 Day 必须恰好返回该 Day 的全部现有 Stop；每个 Stop 只通过 `stopId` 引用。
- 不得输出或重写 Day title/date、Anchor、Stop 的 Candidate/Place identity，也不得改变 Stop 顺序。
- 每个 Stop 必须提供完整的 detailed 字段：activity、period、startTime、endTime、durationMinutes、transportFromPrevious、scheduleVerification、costNote、costVerification、notes。
- startTime/endTime/durationMinutes 必须一致；scheduleVerification 必须存在。没有可靠动态来源时使用 estimated/unverified，不得伪造 verified。
- 可以在确有需要时联网核验动态信息；没有可靠来源时保守表达。
- 不得新增 Place、Candidate、Day、Anchor 或 Stop。
- 不能直接写入 canonical；结果必须经过 Proposal → Apply。
- 如果细化目标必须新增地点，返回 `requiresStage=interests`。
- 只返回 `itinerary.refine.output` 对应 JSON。
