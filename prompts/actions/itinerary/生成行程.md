# 生成行程

目标：使用服务端提供的紧凑 Candidate、Anchor 选项和必要地理聚类，生成全旅程的按天安排。

要求：
- Stop 只能引用输入 candidates 中的 ID；不得把 kind=city 作为 Stop。
- Anchor 只能引用 anchorOptions 中的 placeId；城市可以作为 Anchor，但不得作为 Stop。
- 不输出 Day、Anchor 或 Stop 的正式 ID、日期、坐标、Provider ID、地址、距离、时长或 geometry；这些均由服务端处理。
- 不联网；地图/路线事实只来自服务端输入。
- 不创建新 Place 或 Candidate；输出合同不存在 `newPlaces/newCandidates`。
- 如果完成用户目标必须新增地点或补足可定位地点，返回 `requires_stage` 且 `requiresStage=interests`，不要静默补点。
- must_go 不得静默省略；若是天数、约束或必去规模无法容纳，返回 requires_stage / requirements；若缺地点或定位，返回 interests。
- 每个 Stop 仅输出语义交通方式 transportModeFromPrevious；不要输出交通距离、时长或路线事实。未能确定时输出 none 或 null，绝不默认 walk。
- 只返回 `itinerary.generate.output` 对应 JSON。
