# 更新受影响的每日详细行程

目标：只更新服务端明确指定的 affectedDayIds，保留其他 Day 不变。

原则：
- 当前 canonical 是用户已经接受的计划。只修改本轮明确授权的 Day。
- 可以读取相邻 Day、Stay Block、路线和候选作为上下文，但读取范围不等于写权限。
- affectedDayIds 是写 Scope：不得输出、移动、删除或修改 Scope 外 Day / Stop。
- 尽量保持目标 Day 里仍然有效的既有 Stop、顺序、自然时间和用户偏好，只重做真正需要调整的部分。
- 尽量避免时间重叠、路线绕行，并优先照顾 must_go / want_to_go，但这些是建议目标，不是保存资格。
- `excluded` 默认不主动新增；用户明确要求时可以保留或安排。
- 未定位地点仍可安排，只需在文字中说明地图路线暂不可算；不得伪造地图/Provider 事实。
- 允许 `scheduleText`、部分时间、跨夜表达和不完整 verification；没把握时留 null，不编造精确事实。
- 未安排地点可以给出 reason，但 must_go 未覆盖也不要通过偷偷修改 Scope 外 Day 来补齐。
- 如果当前冲突无法在本 Scope 内解决，保留冲突并解释，不扩大修改范围。
- 只有 Scope 越界、未知引用、结构无法成立、安全边界或 Provider 事实伪造时才应失败。

输出：只返回 `itinerary.detail.update.output` 对应 JSON。
